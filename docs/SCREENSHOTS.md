## 갱신 기준

1. 문서에 소개할 기능이 구현된 커밋을 빌드합니다.
2. 캡처용 데이터가 필요하면 개인 정보가 없는 예시 데이터만 입력합니다.
3. 앱 창 또는 해당 UI만 캡처해 바탕화면과 다른 앱의 정보가 섞이지 않도록 합니다.
4. 가능하면 커서를 창 밖으로 옮긴 뒤 캡처합니다. 보정한 경우 방법을 기록합니다. 읽을 수 있는 해상도의 PNG로 저장하고 README에 상대 경로로 연결합니다.
5. 캡처 날짜, 대상 커밋과 구현 상태를 이 문서에 기록합니다.
6. GitHub에서 이미지 표시와 설명을 확인하고 관련 문서 커밋에 포함합니다.

캡처용 예시 항목 3개를 직접 등록했으며 앱의 자동 생성 데이터는 아닙니다. 완료 체크·통계 캡처에는 동일한 예시 3개 중 2개를 완료 처리했습니다. 우선순위 화면에는 예시 걷기 일정의 우선순위를 높음으로 설정했습니다. 향후 추가할 화면은 메뉴 막대 빠른 보기와 실제 데스크톱 위젯입니다. 예상도나 목업을 추가한다면 실제 실행 화면과 구분해 표기합니다.

## 커서 없는 실제 시연 영상 제작

촬영 도구는 `Tools/demo/build-demo.py`와 `Tools/demo/record.swift`입니다. 촬영용 앱은 현재 앱 UI 소스를 사용하되, 저장소·설정·URL scheme을 분리하고 개인 위젯 발행을 끕니다. 산출물은 Git에서 제외된 `.build/demo.noindex` 안에 생성됩니다. `p2j-demo` URL은 촬영용 앱에서만 사용하며 배포 앱에는 추가하지 않습니다.

```sh
python3 Tools/demo/build-demo.py
xcrun swiftc -parse-as-library Tools/demo/record.swift -o .build/demo.noindex/record
```

촬영용 앱을 실행한 뒤 `record`를 인자 없이 실행하면 그 앱의 창 ID만 출력합니다. 녹화 기능에는 macOS 15 이상과 화면 기록 권한이 필요합니다.

```sh
.build/demo.noindex/record
.build/demo.noindex/record WINDOW_ID /absolute/path/demo.mp4
```

녹화 중에는 촬영 앱을 실제로 조작합니다. 출력 파일 경로 뒤에 `.stop`을 붙인 빈 파일을 만들면 정상 종료하며, 최대 180초에 자동 종료합니다. 같은 출력 파일이 이미 있으면 덮어쓰지 않습니다.

녹화는 촬영용 앱의 창 영역만 포함하고 `showsCursor = false`, 시스템 오디오·마이크 수집 해제를 적용합니다. 개인 앱 화면이나 다른 앱을 포함하지 않습니다. 앱 창 위치·크기는 녹화 중 바꾸지 않습니다. 배포할 영상은 실제 조작이 읽히는 속도로 다듬고, 추출 프레임으로 커서·개인 정보·잘린 UI 여부를 검수한 뒤 README의 해당 기능 설명에 연결합니다. GIF 미리보기와 MP4 원본을 제공할 경우 각 파일을 실제 촬영 결과로 생성합니다.

2026-09-27: 촬영용 앱 빌드와 격리된 등록·하위 체크·완료·통계 API 검증을 완료했습니다. ScreenCaptureKit 녹화는 macOS 화면 기록 권한 거부로 아직 촬영하지 못했으며, 촬영하지 않은 영상을 README에 완료된 시연으로 표시하지 않습니다.
