# 개발 가이드

[← README](../README.md)

## 환경

macOS 14 이상과 Swift 6을 지원하는 Xcode 16 이상을 사용합니다. 현재 빌드 검증 환경은 Xcode 26.5입니다. 외부 라이브러리나 프로젝트 생성 도구 설치는 필요하지 않습니다.

`P2J.xcodeproj`를 열고 `P2J` 스킴 및 `My Mac`을 선택합니다. 앱을 빌드하면 의존성으로 연결된 `TODOFirstWidgets` 확장도 함께 빌드되어 앱에 포함됩니다.

## 개발 서명

저장소 루트에서 개인 설정 예시를 복사합니다.

```sh
cp Configuration/Local.xcconfig.example Configuration/Local.xcconfig
```

`Local.xcconfig`의 `DEVELOPMENT_TEAM`을 본인의 Apple Developer Team ID로 변경합니다. 필요하면 `BUNDLE_ID_PREFIX`도 본인이 사용할 고유 식별자로 변경합니다. 실제 Team ID 확인과 계정 연결은 Xcode의 **Settings → Accounts**에서 진행합니다.

`Local.xcconfig`는 Git에서 제외됩니다. 인증서, 프로비저닝 프로파일, 인증 정보는 저장소에 추가하지 않습니다.

두 타깃 모두 App Sandbox가 활성화되어 있습니다. App Groups 권한과 위젯용 스냅샷 저장소를 구성했습니다. 서명 설정과 검증 방법은 [위젯 가이드](WIDGETS.md)에 있습니다.

## 빌드 검증

```sh
xcodebuild \
  -project P2J.xcodeproj \
  -scheme P2J \
  -configuration Debug \
  -destination 'generic/platform=macOS' \
  -derivedDataPath build \
  CODE_SIGNING_ALLOWED=NO \
  build
```

서명을 생략한 컴파일·패키징 검증입니다. 위젯의 실제 등록, 앱 배포 서명, 공증을 대신하지 않습니다.

### 핵심 로직 테스트

```sh
swift test
```

외부 의존성 없는 Swift 패키지로 일정 모델과 저장소를 검사합니다. Xcode 앱은 같은 소스를 직접 빌드하므로 별도 패키지 연결은 필요하지 않습니다.

43개 테스트가 일회성·매일·평일·매주 일정, 시간대 이동, 저장·재로딩, 삭제, 빈 제목 차단, 손상 파일 보존, 실제 파일 쓰기 실패 시 상태 보존을 검증합니다. 날짜별 완료·취소, 구버전 파일 호환, 통계 합계·기간·삭제 이력 보존도 검사합니다.

## 현재 데이터 동작

- `Application Support/TODOFirst/tasks.json`에 버전 정보를 포함한 JSON을 원자적으로 저장합니다. 서명된 샌드박스 앱에서는 앱 컨테이너 안의 Application Support를 사용합니다.
- 시작일은 시각 대신 연·월·일로 저장하고, 현재 달력을 기준으로 해당 날짜에 표시할지 계산합니다.
- 일회성 일정은 지정한 날만 표시됩니다. 과거 항목도 삭제하지 않으며 전체 목록에 남습니다.
- 매일·평일·매주 일정은 시작일 이전에 표시되지 않습니다. 평일은 월~금이며 공휴일 제외 기능은 없습니다.
- 날짜별 목록은 화면에서 30초 간격으로 다시 계산합니다.
- 제목은 공백만 입력할 수 없으며 120자, 메모는 2,000자까지 허용합니다.
- 불러오기 실패 시 변경을 막아 기존 파일을 보존하고 오류를 표시합니다. 저장 실패 시 목록을 먼저 변경하지 않으며 등록 폼도 닫지 않습니다.
- 완료 날짜를 항목별로 저장하며, 반복 일정은 다음 날 독립적으로 체크할 수 있습니다.
- 삭제는 일정 보관 처리로 구현합니다. 삭제일부터 새로운 발생을 중단하고 과거 통계와 완료 기록은 보존합니다. 복원 UI는 아직 없습니다.
- 저장 버전은 5이며 버전 1·2·3·4 파일을 읽을 수 있습니다. 없는 완료 기록은 빈 목록, 없는 우선순위는 보통으로 보완합니다.
- 개별 날짜 건너뛰기 기능은 아직 없습니다.

메뉴 막대는 앱과 같은 TaskStore를 사용하며 오늘의 목록에서 완료·취소 및 우선순위 변경을 처리합니다. 위젯에는 원본을 이동하지 않고 활성 일정의 표시용 복사본을 전달합니다. 기존 할 일과 완료 이력은 원래 저장소에 유지됩니다. 공유 실패 시 앱 저장을 막지 않으며 위젯 연결 화면에서 오류를 표시합니다.

위젯 테스트는 스냅샷 저장·읽기, 메모·보관 항목 제외, 오늘/내일 완료 상태, 빈 목록·모두 완료, 서머타임 오전 6시 엔트리, 손상 데이터, 성공한 변경만 전달하는 동작을 검증합니다.

## 위젯 확인

앱 하단 **위젯 보기**에서 현재 일정으로 소형·중형 미리보기를 확인합니다. 실제 데스크톱 등록, 서명, App Group과 갱신 검증은 [위젯 가이드](WIDGETS.md)를 따릅니다. 개발 서명 인증서가 없는 환경에서는 미리보기와 빌드만 검증할 수 있습니다.

## 커밋 기준

프로젝트 구성, 로컬 저장, 할 일 편집, 우선순위, 메뉴 막대, 위젯 등 변경 목적별로 커밋합니다. 해당 변경의 빌드·테스트·문서 확인을 마친 뒤 커밋하고, 아직 구현되지 않은 기능을 완료로 표시하지 않습니다.

## 배포 전 작업

- 기능별 동작과 날짜 전환·데이터 보존 검증
- 앱 아이콘과 배포 메타데이터 준비
- App Groups 및 앱·위젯 서명 확인
- Developer ID 서명, 공증과 배포 패키지 준비
- 실제 설치 환경에서 앱 실행·위젯 등록 확인
- 라이선스, 릴리스 노트, 설치 안내 작성

현재 설치용 파일과 정식 릴리스는 제공하지 않습니다.

## P2J 이름 변경과 데이터 호환

GitHub 저장소와 로컬 폴더, Xcode 프로젝트·공유 스킴, 앱 제품 이름은 P2J입니다. 기존 등록 데이터를 유지하기 위해 내부 타깃 이름(TODOFirst), 번들 식별자와 Application Support/TODOFirst 저장 위치는 유지합니다. 빌드 명령과 Xcode 실행에서는 P2J 스킴을 선택합니다.

## 우선순위와 메뉴 막대

우선순위는 높음·보통·낮음이며, 활성 일정만 변경할 수 있습니다. 변경 시 완료 기록을 유지하고 저장 성공 후 위젯용 복사본을 갱신합니다. 앱과 메뉴 막대는 미완료를 먼저, 그 안에서 우선순위·등록 시각·식별자 순으로 정렬합니다. 위젯도 같은 정렬 함수를 사용합니다.

추가 테스트는 우선순위가 없는 이전 파일, 완료 여부와 우선순위 정렬, 저장·재실행·갱신 알림, 저장 실패 시 기존 값 보존, 위젯 정렬 일치를 검사합니다. 메뉴 막대도 날짜 변경을 30초 간격으로 다시 계산하며 저장 오류를 팝오버에 표시합니다.

## 할 일 수정

목록의 연필 버튼은 등록 폼에 기존 값을 불러옵니다. 저장 시 제목·메모·우선순위·반복·시작일만 변경하고, ID·등록 시각·최신 완료 기록은 유지합니다. 취소는 저장소를 변경하지 않습니다. 반복 일정 전체에 적용되며 일정 변경 시 과거 계획 수는 새 규칙으로 계산합니다. 기존 완료 실적은 유지합니다. 저장 실패 시 폼과 기존 저장 상태를 유지합니다. 수정 후 데이터는 메뉴 막대와 위젯 스냅샷에도 전달되며 위젯 표시 갱신 시점은 macOS가 결정합니다.

수정 회귀 테스트는 최신 완료 기록 보존, 저장 후 재로딩, 일정·통계·위젯 데이터 반영, 잘못된 입력, 파일 쓰기 실패, 삭제된 항목 수정 거부를 검증합니다.

## 오전 6시 작업일 경계

TaskClock은 실제 시각을 현지 오전 6시 기준의 작업일로 변환합니다. 앱·메뉴 막대의 오늘 표시와 통계 입력, 완료·삭제 처리, 등록 기본값 및 오늘 버튼, 위젯에 동일한 기준을 적용합니다. 사용자가 지정한 날짜와 기존 저장 기록은 이동하지 않습니다. 화면은 30초 간격으로 갱신하며 위젯은 오전 6시 타임라인을 준비합니다. 실제 위젯 갱신 시점은 macOS가 관리합니다. 완료 기록을 삭제하는 초기화는 하지 않습니다.

## 기간 작업과 하위 TODO (v4)

저장 형식 v4는 `endDay`와 `subtasks`를 추가합니다. v1~v3 파일도 읽으며 누락된 하위 항목은 빈 배열로 해석합니다. 기존 weekdays 일정은 보존하되 신규 선택에서는 제외합니다. 기존 평일 일정 편집 시 매일을 기본 제안하고 변경 안내를 표시하며 취소하면 저장하지 않습니다.

기간 작업은 시작·종료일을 포함합니다. 종료일 누락·역전은 저장을 거부합니다. 기간 완료는 한 번 체크하면 유지하고 취소하면 해제합니다. 통계의 완료 실적은 실제 완료 날짜에만 집계하며, 완료 전 기간의 각 날짜는 계획에 포함합니다. 오늘 달성률은 목록과 동일한 기준입니다. 기간 종료 후에는 전체 목록에서 확인합니다.

하위 TODO는 한 단계 체크리스트입니다. 자체 일정 대신 부모 일정을 따릅니다. 반복 작업은 날짜별 완료, 기간 작업은 지속 완료입니다. 하위 항목의 체크는 부모를 자동 완료하지 않으며 통계·위젯은 부모 기준이며 메뉴 막대에서는 부모·하위 항목을 모두 체크할 수 있습니다. 수정 시 동일 ID의 최신 하위 완료 기록을 유지하고 삭제된 하위 항목은 제거합니다.

제목 필드는 NSTextField의 연속 변경 알림으로 공백과 한글 입력을 상태에 전달합니다. 활성 편집기의 문자열을 재설정하지 않고 저장 직전 편집을 확정합니다. 실제 폼에서 공백 입력 직후 값·저장 버튼 갱신, 기간 선택, 하위 항목 입력, 취소를 확인했습니다. 테스트는 기간 경계·완료 집계·저장 복원·하위 체크 및 실패 시 상태 보존·이전 형식 호환을 포함합니다.

## 입력 화면과 메뉴 막대 UI

등록·수정 화면은 카드형 입력, 우선순위·일정 선택 버튼, 시작·종료 날짜 카드로 구성합니다. 날짜 카드의 달력 팝오버는 현지 달력의 요일 순서와 월별 날짜 수를 사용하며 오늘 선택은 오전 6시 기준입니다. 제목의 연속 입력 처리는 유지합니다. 메뉴 막대는 하위 TODO의 개별 체크와 완료 개수를 표시하며 앱과 동일한 TaskStore 및 완료 판정 함수를 사용합니다. 반복 하위 체크의 날짜별 초기화와 기간 하위 체크 유지도 공유합니다.

## 실제 작업 시각 (v5)

`activities`에 작업일, 실제 시작·완료 Date를 저장합니다. 이전 데이터에는 빈 배열을 사용하며 완료 시각을 만들어내지 않습니다. 시작은 명시적 버튼으로 기록하고 완료 체크는 시작 없이도 가능합니다. 완료 취소는 종료 시각만 지우고 시작을 유지하며, 시작도 없는 빈 기록은 제거합니다. 반복 작업은 오전 6시 작업일별, 기간 작업은 마지막 활동을 이어 사용합니다. 저장 실패 시 시각과 완료 상태 모두 이전 값으로 유지됩니다.

통계 작업 기록은 완료 시각의 작업일(미완료는 시작 작업일)에 귀속됩니다. 기간 내 완료됐고 시작·종료가 모두 있는 기록만 평균 경과 시간에 포함합니다. 휴식·앱 종료 시간을 빼지 않으며 집중 시간으로 표현하지 않습니다. 오래된 완료 날짜에는 시각 기록 없음이 표시됩니다. 우선순위 집계는 현재 우선순위 기준이고, 기간 비교는 직전 동일 일수와 완료 건수를 비교합니다.

## 유형별 집계와 수동 시간 기록

통계 합계는 TaskStatistics.summary를 사용합니다. 기간 작업은 조회 범위와 겹친 작업당 한 건(범위 이전에 완료한 작업 제외), 반복 일정은 해당 날짜마다 한 회, 하루 작업은 해당 날짜 한 건입니다. 일별 차트는 기간 작업을 제외해 합계와 별도 의미임을 명시합니다. 우선순위별 성과와 이전 기간 비교도 동일 summary를 사용합니다.

TaskStore.recordTiming은 날짜별 실제 시각을 교체하고 완료 상태도 함께 반영합니다. 반복 일정은 시작·완료 모두 같은 오전 6시 작업일 안에 있어야 하며 기간 작업은 여러 날에 걸칠 수 있습니다. 미래·역전·일정 밖 기록은 저장하지 않습니다. 자동화도 이 메서드와 같은 검증을 사용합니다.
